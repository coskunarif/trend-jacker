# SPEC.md: Optimize Search Query Alignment and URL Readability

## Acceptance Criteria

- **[AC-1] Eliminate Hard-coded Character Truncation on Reddit Trend Titles**
  - **Description**: The hard-coded 60-character truncation logic (`title.substring(0, 60) + '...'`) in the Reddit RSS feed parser must be removed. The full thread title must be used.
  - **Verification**: Ingest or mock a Reddit RSS item with a title longer than 60 characters (e.g. 100 characters). The stored trend title must match the full, untruncated text exactly.

- **[AC-2] Full & Search-friendly Slug Generation for Trend URLs**
  - **Description**: Slugs generated by `titleToSlug` for long Reddit trends must map cleanly to the full, untruncated title. Slugs must not contain trailing `...` or cut-off words. They must transliterate accents, limit slug length to 100 characters truncated on a word boundary (last index of `-`), and fall back to a hashed trend format if no alphanumeric characters remain.
  - **Verification**: 
    - Verify that `titleToSlug("World Cup tourists: what's your honest feedback on the USA's stadiums")` generates `world-cup-tourists-whats-your-honest-feedback-on-the-usas-stadiums`.
    - Verify that a Japanese title like `世界カップへようこそ` (which has no alphanumeric chars) generates a slug format of `trend-${hash}` where `${hash}` is a short alphanumeric string representing the hash of the title.
    - Verify that a slug longer than 100 characters is truncated to at most 100 characters at the last `-` character boundary.
    - Accessing these routes in the dev server must render the details view with status `200`.

- **[AC-3] Dynamic Sitemap and Indexing API Synchronization**
  - **Description**: Dynamic sitemap (`sitemap.xml`) generation and search engine pings via Google Indexing API & IndexNow must utilize the untruncated slugs generated from the full trend titles.
  - **Verification**: Retrieve `/sitemap.xml` after a long Reddit trend is cached. The URL in `<loc>` tags must use the untruncated, search-friendly slug. The indexing ping script must successfully process and format all 4 localized variants using the untruncated slug.

- **[AC-4] UI Layout and Responsive Presentation of Long Titles**
  - **Description**: The UI layout must remain visually unbroken when displaying long trend titles. Long titles in both the sidebar/trend list and the detail page header must wrap naturally using CSS properties (`word-wrap: break-word` and `overflow-wrap: break-word`), ensuring no horizontal overflow or text overlap on mobile (375x667) and desktop (1280x800) viewports.
  - **Verification**: Playwright responsive viewport check ensures no horizontal scrolling (`window.innerWidth >= document.documentElement.scrollWidth`).

- **[AC-5] Firestore Document ID Hashing/Subcollection Path Collision Avoidance**
  - **Description**: All document IDs used for Firestore must be fully sanitized and hashed using `getFirestoreDocId` (SHA-256 hash) to prevent subcollection path collisions when trend titles or client IDs contain forward slashes or other unsafe characters.
  - **Verification**: Saving and retrieving records for `polls`, `trend_explanations`, `localized_explanations`, `topic_images`, and `client_chat_counts` must utilize hashed document IDs. In `getAllCachedExplanations`, the actual human-readable trend name must be retrieved from the `trend` document field instead of relying on the document ID.

- **[AC-6] Persistent Search Engine Indexing Pings**
  - **Description**: The indexing status of trend slugs must be persisted in SQLite and Firestore using a dedicated `pinged_slugs` table and collection. The server must check this persistent store before triggering IndexNow or Google Indexing API pings to avoid duplicate requests and quota exhaustion.
  - **Verification**: Triggering cache updates repeatedly or restarting the server must not produce duplicate indexing pings for previously processed slugs.

- **[AC-7] Strict 404 for Arbitrary/Fake Slugs**
  - **Description**: The `/t/:slug` and `/t/:slug/:lang` route handlers must return a `404 Not Found` response if the slug is not found in the live trends cache (`latestTrends`), Google RSS live feed, or historically cached trend explanations database (via `getAllCachedExplanations`). It must not attempt to dynamically generate trend explanations for arbitrary or fake slugs.
  - **Verification**: Requesting a non-existent slug (e.g., `/t/fake-unseen-trend-slug`) must return an HTTP status `404` instead of invoking the Gemini API.

## Interface Contract

- **`titleToSlug(title)` Function** (inside `server.js` and `public/app.js`):
  - Signature: `function titleToSlug(title: string): string`
  - Input: Full untruncated trend name or post title.
  - Normalization: Strip diacritics using `.normalize("NFD").replace(/[\u0300-\u036f]/g, "")`.
  - Truncation: Maximum 100 characters, truncated at the last `-` word boundary.
  - Fallback: Return `trend-${hash}` if the result contains no alphanumeric characters, where the hash is computed via a simple deterministic 32-bit string hash represented as a base36 string.
- **`latestTrends` Array** (inside `server.js`):
  - Type: `Array<TrendItem>`
  - Field: `title` in each `TrendItem` must represent the full, untruncated trend title.
- **`getFirestoreDocId(key)` Helper** (inside `db.js`):
  - Signature: `function getFirestoreDocId(key: string): string`
  - Behavior: Computes SHA-256 hex digest of key. Used for all Firestore document paths in `polls`, `trend_explanations`, `localized_explanations`, `topic_images`, and `client_chat_counts`.
- **Indexing Status Persistence Functions** (inside `db.js`):
  - `isSlugPinged(slug: string): Promise<boolean>`
  - `markSlugAsPinged(slug: string): Promise<void>`
  - Uses SQLite `pinged_slugs` table and Firestore `pinged_slugs` collection.

## Objections and Resolutions

- **Critic Objection 1 (Empty or Invalid Slugs for Non-ASCII/Non-English Trend Titles)**:
  - **Resolution**: Accented characters will be transliterated/normalized out. If the resulting slug contains no alphanumeric characters (e.g. Japanese), it falls back to `trend-${hash}` using a deterministic base36 string hash function.
- **Critic Objection 2 (Unbounded Slug Lengths for Long Reddit Trends)**:
  - **Resolution**: Generated slugs will be truncated to a maximum of 100 characters on a word boundary (at the last `-` index), preventing excessively long URLs and potential HTTP 414 responses.
- **Critic Objection 3 (Firestore Document ID Slashes/Subcollection Path Collision)**:
  - **Resolution**: All document IDs in Firestore collections will be hashed using SHA-256 (`getFirestoreDocId`). The original human-readable trend title will be stored in the document fields (e.g., `trend` field) to ensure correct retrieval in `getAllCachedExplanations`.
- **Critic Objection 4 (Volatile In-Memory `pingedSlugs` Cache)**:
  - **Resolution**: Indexing status is persisted in a dedicated SQLite table `pinged_slugs` and Firestore collection `pinged_slugs`, checking this store before any pings to avoid quota exhaustion on restarts.
- **Critic Objection 5 (Unvalidated Dynamic Explanation Generation for Arbitrary/Fake Slugs)**:
  - **Resolution**: Enforce strict verification on `/t/:slug` and `/t/:slug/:lang` routes. If a slug is not present in live trends, Google RSS feed, or historical DB records (obtained via `getAllCachedExplanations()`), the server immediately returns a `404 Not Found` response.
